# 13 裸机框架（C 语言）

本工程 **没有 FreeRTOS / 没有线程**。所谓框架，就是：

1. `main` 里死循环  
2. 循环里跑两套「到点就调函数指针」的调度  
3. 再加一个 10ms 硬件定时器中断，处理必须更勤的采样  

源码：`USER/main.cpp`、`USER/HAL/HAL.cpp`、`Libraries/MillisTaskManager/`。

---

## 1. 和 RTOS 差在哪

| | 本工程裸机 | FreeRTOS |
|--|-----------|----------|
| 并发 | 一个 `for(;;)`，任务轮流跑完 | 多个任务可抢占 |
| 阻塞 | 某个函数卡住，整机卡住 | 一个任务 delay，别人还能跑 |
| 同步 | 不需要 mutex（单线程） | 队列、信号量 |
| 空闲 | `__wfi()` 等中断 | idle 任务 |

所以 GPS 解析、刷屏、写 SD **都不能死等很久**。长操作要拆开，或接受这一圈 loop 变慢。

C 入口就是 Arduino 那套 `setup` + `loop`，底下仍是标准 `main`：

```c
int main(void)
{
    Core_Init();          /* 时钟、GPIO 等 MCU 底层 */
    setup();
    for (;;)
        loop();
}

static void setup(void)
{
    HAL_Init();           /* 外设 + 注册周期任务 + 10ms 中断 */
    lv_init();
    lv_port_init();       /* 显示 / 编码器 / SdFat 接到 LVGL */
    App_Init();           /* DataProc、页面栈、Push Startup */
    Power_SetEventCallback(App_Uninit);  /* 关机前存盘 */
}

static void loop(void)
{
    HAL_Update();         /* MillisTaskManager：GPS/SD/电源事件... */
    lv_task_handler();    /* LVGL：动画、刷新、Account 的 lv_timer */
    __wfi();              /* 等中断（滴答、10ms 定时器、串口）再醒 */
}
```

对应 `USER/main.cpp`。`__wfi()` 不是休眠关机，是「没中断就停核」，省一点电；有 SysTick 仍会定期醒来。

## 2. 三层时间源（不要混在一起）

```
[10ms 定时器中断]     Power_Update / Encoder_Update / Audio_Update
        |
        |  不能做 LVGL、不能 printf 太久
        v
[主循环 HAL_Update]   MillisTaskManager 按 ms 调 HAL 任务
        |
        v
[主循环 lv_task_handler]  LVGL timer：页面 Update、DataCenter Account 周期
```

### A. 中断里（10ms）

`HAL.cpp`：

```c
static void HAL_TimerInterrputUpdate(void)
{
    HAL_Power_Update();
    HAL_Encoder_Update();
    HAL_Audio_Update();
}

Timer_SetInterrupt(TIM_x, 10 * 1000, HAL_TimerInterrputUpdate);
```

编码器、蜂鸣器、电源键必须短周期采样，放主循环会漏脉冲。C 里就是 TIM 中断 ISR 调三个函数，**保持很短**。

### B. 主循环合作式任务（MillisTaskManager）

库自己说：超轻量分时合作式调度，替代满地 `if (millis()-last > 200)`。

C 模型：

```c
typedef void (*task_fn_t)(void);

typedef struct Task {
    task_fn_t fn;
    uint32_t period_ms;
    uint32_t last_tick;
    struct Task *next;
} Task;

void MTM_Running(uint32_t now)
{
    Task *t;
    for (t = head; t; t = t->next) {
        if (now - t->last_tick >= t->period_ms) {
            t->last_tick = now;
            t->fn();          /* 跑完才轮到下一个，无抢占 */
        }
    }
}

void HAL_Update(void)
{
    MTM_Running(millis());
}
```

本工程注册的（`HAL_Init`）：

| 函数 | 周期 | 干什么 |
|------|------|--------|
| Power_EventMonitor | 100 ms | 开关机、低电 |
| GPS_Update | 200 ms | 从串口抠 NMEA |
| SD_Update | 500 ms | 卡插拔 |
| IMU/MAG_Update | 1000 ms | 有传感器才注册 |
| Memory_DumpInfo | 1000 ms | 栈/堆统计 |
| WDG_ReloadCounter | 超时/10 | 喂狗 |

`Register(fn, timeMs)` = 往链表加一个节点。没有优先级抢占（构造时 `priorityEnable` 默认 false）。

### C. LVGL 定时器（也在主循环，但另一套）

`lv_task_handler()` 内部跑所有 `lv_timer`。DataCenter 的 `Account_SetTimerPeriod(1000)`、表盘 `lv_timer_create(..., 1000, d)` 都在这里。

所以：**HAL 的 GPS_Update（200ms 收串口）** 和 **DP_GPS 的 Account Timer（1000ms 读 HAL 再 Publish）** 是两层。底层灌缓冲，应用层按 1Hz 取结构体。

## 3. 启动顺序（setup 在干什么）

```
Core_Init
  HAL_Init
    串口、HardFault 回溯、电源/背光/编码器/RTC/GPS/I2C 传感器/音频/SD/屏
    注册 MillisTask
    打开 10ms TIM
  lv_init + lv_port_init     显示缓冲、输入设备、文件系统
  App_Init
    DataProc_Init            13 个 Account
    Storage/SysConfig LOAD
    ResourcePool
    StatusBar（画在 lv_layer_top）
    PageManager Install 各页
    Push("Pages/Startup")
  绑定关机回调 App_Uninit
```

关机：电源任务发现长按 → 调 `App_Uninit`（存 JSON、停 Recorder）→ 再断电。不是 RTOS 的 shutdown 钩子，就是函数指针。

## 4. 一张图：一圈 loop 里实际跑了谁

```
loop:
  HAL_Update
      GPS_Update          解析串口 -> HAL 里那份 GPS_Info
      SD_Update
      Power_EventMonitor
      ...
  lv_task_handler
      刷屏
      处理编码器 group
      Account TIMER: DP_GPS Commit+Publish
      Account TIMER: SportStatus Pull GPS 算速度 Publish
      页面 timer: Dialplate Update 写 Label
  WFI
```

全程一个栈（主栈 MSP）。没有线程栈。CmBacktrace 裸机配置 `CMB_USING_BARE_METAL_PLATFORM` 就是因为这个。

## 5. 写新功能时放哪一层

| 你要做的事 | 放哪 |
|------------|------|
| 必须 <10ms 采样（编码器、按键消抖） | 10ms ISR，函数要短 |
| 周期读外设、不碰 LVGL | `taskManager.Register(fn, ms)` |
| 算业务、Publish 给页面 | DataProc Account Timer（在 lv_task_handler 里） |
| 改某个 Label | 页面自己的 lv_timer，或 Appear 时 Update 一次 |
| 等 GPS 定位再往下 | 状态机 + Pull，**不要**在 loop 里 `while(!fix)` |

若在 ISR 或 HAL 任务里调 `lv_label_set_text`，可能和 `lv_task_handler` 交错改同一控件（单线程仍可能重入：ISR 打断 loop）。LVGL 只在主循环、非 ISR 里用。

## 6. 和「应用框架」的关系

裸机框架只管 **谁在什么节拍被调用**。  
页面 MVP、DataCenter 是跑在 `lv_task_handler` 里的应用框架，见：

- [06-页面框架-C语言说明.md](06-页面框架-C语言说明.md)
- [07-数据流-C语言说明.md](07-数据流-C语言说明.md)

可以记：

- **裸机框架** = `main` + MillisTaskManager + 10ms ISR + `lv_task_handler`  
- **应用框架** = PageManager + DataCenter + 各 DP 节点
