# 16 页面生命周期：设计思想与实现

对应学习路径第 1 条。调度器 API 细表见 [14-PageManager-C语言.md](14-PageManager-C语言.md)。  
本文回答：**为什么要状态机，以及一次切页在源码里实际跑什么。**

源码：`Utils/PageManager/`，样板页 `Pages/Dialplate/Dialplate.cpp`。

---

## 1. 设计要解决什么

LVGL 没有「Activity」。多页面时，容易写成：

```c
void ui_task(void)
{
    if (page == DIAL) {
        lv_label_set_text(...);
        if (btn_map) page = MAP;
    }
}
```

缺的是**成对的时机**：

| 没有固定时机时 | 实际故障 |
|----------------|----------|
| 切走还不删 1s timer | 回调改已经隐藏/删除的控件 → 花屏或 HardFault |
| 编码器 group 不摘 | 地图页和表盘抢同一颗旋钮 |
| 控件创建时机随便 | 动画播到一半对象没了，或重复 create 泄漏 |
| 用一个全局 `g_page` | 返回时不知道「底下是谁」，多层菜单全靠 if |

设计目标：把「创建 / 显示 / 隐藏 / 销毁」写成**调度器强制调用的合同**。页面只填回调，不许自己 `lv_scr_load`。

思想来源接近 Android Activity，但实现是裸机上的合作式状态机，不是系统组件。

---

## 2. 核心思想（四条）

1. **页面是带回调表的对象**，不是页号。调度器只认 `PageBase*`。
2. **池和栈分开。** Install 时 new 进池（对象一直活着）；Push 只把指针压栈。
3. **显示和存在不是一回事。** 有缓存：切走隐藏 `_root`；无缓存：UNLOAD 删控件，对象仍在池里。
4. **切页是异步的。** 本次调用只走到 WILL_APPEAR 并启动动画；DID_APPEAR 在动画结束回调里。

C 里就是：结构体公共头 + 函数指针 + `switch(state)`。`virtual onViewLoad` 就是函数指针。

## 3. 实现落地

### 3.1 合同写在 PageBase

`PageBase.h` 规定每个页面必须能被调到的函数（默认空实现）：

```
onCustomAttrConfig   Install 后立刻，尚未 LOAD。只配缓存/动画。
onViewLoad           创建 Model/View，绑事件。此时 _root 已有。
onViewDidLoad
onViewWillAppear     挂输入、刷一帧、播入场。
onViewDidAppear      开周期 timer。
onViewWillDisappear  停 timer、摘 group、记焦点。
onViewDidDisappear
onViewUnload         Model.Deinit、View.Delete。
onViewDidUnload
```

页面另有三个调度器填的指针：`_root`、`_Manager`、`_Name`。  
`_Manager` 就是 `App.cpp` 里那一个 `PageManager`，所以页面里可以 `_Manager->Push(...)`。

### 3.2 状态机在 PM_State.cpp

`StateUpdate(page)` 按 `priv.State` 走一步，并调用上面那些函数。

```
IDLE → LOAD → WILL_APPEAR → DID_APPEAR → ACTIVITY
              ↑                              │
              └── 有缓存：隐藏 root ─────────┤ 离开
                   无缓存：UNLOAD → IDLE  ←──┘
```

LOAD 里：`lv_obj_create(lv_scr_act())` 当 `_root`，再 `onViewLoad`。  
UNLOAD 里：`lv_obj_del_async(_root)`，避免动画没完就删对象。

**资源钉在哪一侧：**

| 申请 | 必须释放的对称点 |
|------|------------------|
| `onViewLoad` 里 Model.Init / View.Create | `onViewUnload` |
| `onViewDidAppear` 里 `lv_timer_create` | `onViewWillDisappear` 里 `lv_timer_del` |
| `onViewWillAppear` 里 `lv_group_add_obj` | `onViewWillDisappear` 里 `remove_all` |

表盘就是按这张表写的。漏一对就会在切到地图后还刷表盘 Label。

### 3.3 路由在 PM_Router.cpp

| API | 栈 | 旧页 |
|-----|----|------|
| Push | 新页压栈 | 走离开流程，默认可缓存 |
| Pop | 弹出当前 | 自动缓存时强制卸被弹出页 |
| Replace | 弹出栈顶再压新页 | 强制 `IsCached=false`（开机用） |

都先检查动画忙不忙；忙就失败。同一页不能在栈里出现两次。

最后都进 `SwitchTo`：拷 stash → 新页设 LOAD 或 WILL_APPEAR（已缓存）→ `StateUpdate(旧)` → `StateUpdate(新)` → 调图层 → 动画 ready 后再 StateUpdate 一次。

### 3.4 工厂：按字符串 new

`Install("Dialplate", "Pages/Dialplate")`：第一个给 `AppFactory::CreatePage`，第二个当 `_Name` 和以后 Push 的参数。  
Push 用 `"Pages/Dialplate"`，不是 `"Dialplate"`。

## 4. 跟一次真实切页

表盘短按地图：`_Manager->Push("Pages/LiveMap")`。

```
1. FindPageInPool("Pages/LiveMap")  → 池里那个对象（Install 时就 new 了）
2. 压栈： [Dialplate, LiveMap]
3. SwitchTo(LiveMap, is_enter=true)
4. Dialplate: ACTIVITY → WILL_DISAPPEAR
      存焦点、摘 group、删 1s timer、onViewWillDisappear
      开离开动画
5. LiveMap: 无缓存 → LOAD
      建 root、onViewLoad（建瓦片控件）
      → WILL_APPEAR（Init 总线账号、黑状态栏）
6. 动画结束
      Dialplate DID_DISAPPEAR，有缓存 → 隐藏 root，状态变 WILL_APPEAR
      LiveMap DID_APPEAR → 开 100ms timer
7. 用户在地图按返回 Pop
      LiveMap 关缓存 → UNLOAD（卸瓦片，省 RAM）
      Dialplate 已缓存 → 只 WILL_APPEAR，恢复 group 和 1s timer
```

开机是另一条：`Push Startup` → 2s 后 `Replace Dialplate`。Startup 关缓存，Replace 再强制卸，栈底只剩表盘。

---

## 5. 自己做时的最小合同

不必抄动画。每个页面保证：

```c
on_load:      xxx_init();  create_widgets(root);
on_appear:    group_add(); start_or_not_timer 可放 did_appear;
on_disappear: group_clear(); timer_del();
on_unload:    xxx_deinit();  /* 不要 lv_obj_del(root)，交给调度器 */
```

跳转只调用 `manager->Push/Pop`，不要 `lv_scr_load`。
