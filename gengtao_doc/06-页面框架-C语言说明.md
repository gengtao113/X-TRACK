# 06 页面框架：用 C 语言怎么理解

面向对象的 C++ 在本仓库里主要干一件事：**给每个页面规定一套必须实现的回调，再由调度器按时去调**。  
对只用 C 的人，这就是「结构体 + 函数指针表 + 状态机」，和写 LVGL、写协议栈、写菜单树是同一类手法。

本文把 `04-页面框架.md` 翻成 C 的说法，说明这套框架好在哪里。对应源码仍是 C++，不必先会 class 语法。

PageManager 调度器（页面池、栈、Push/Pop/Replace、缓存、动画）的对照源码总结见：[14-PageManager-C语言.md](14-PageManager-C语言.md)。

---

## 1. 没有这套框架时，C 工程通常长什么样

很多 MCU + 屏的 C 项目会写成：

```c
void ui_task(void)
{
    switch (g_page) {
    case PAGE_DIAL:
        gps_read();                 /* 读硬件 */
        speed = calc_speed();       /* 算业务 */
        lv_label_set_text(...);     /* 画界面 */
        if (btn_map) g_page = PAGE_MAP;
        break;
    case PAGE_MAP:
        /* 地图页又把 GPS、SD、画线揉在一起 */
        break;
    }
}
```

问题很具体：

- 切走表盘时，1 秒刷新定时器还在跑，可能改已经删掉的控件
- 编码器焦点没摘干净，地图页和表盘抢同一个输入
- 换 GPS 模块时，每个页面里的 `gps_read()` 都要改
- 想加一页，只能把 `switch` 再拉长

PageManager 要解决的就是：**谁创建控件、谁刷新、谁释放、谁处理输入，全部有固定时机**。

## 2. C++ 的 class，对应 C 里什么

### 页面基类 = 带函数指针的结构体

源码里 `PageBase` 声明了一组 `onViewLoad` / `onViewDidAppear` ...  
用 C 写，就是每个页面一份「操作表」：

```c
typedef struct Page Page;

typedef struct {
    void (*on_load)(Page *page);           /* 创建控件、申请资源 */
    void (*on_did_load)(Page *page);
    void (*on_will_appear)(Page *page);    /* 即将显示：挂输入、播动画 */
    void (*on_did_appear)(Page *page);     /* 已经显示：开定时器 */
    void (*on_will_disappear)(Page *page); /* 即将离开：停定时器、摘输入 */
    void (*on_did_disappear)(Page *page);
    void (*on_unload)(Page *page);         /* 删控件、释放资源 */
    void (*on_did_unload)(Page *page);
} PageOps;

struct Page {
    const char   *name;
    lv_obj_t     *root;        /* 这一页的 LVGL 根对象 */
    const PageOps *ops;        /* 本页自己的回调表 */
    int           state;       /* 生命周期状态 */
    void         *priv;        /* 本页私有数据 */
};
```

调度器 **不关心** 这是表盘还是地图，只做：

```c
if (page->ops->on_did_appear)
    page->ops->on_did_appear(page);
```

这和 STM32 HAL 的 `UART_HandleTypeDef` 里挂回调、或者 Linux 驱动 `file_operations` 是同一个思路：  
**公共调度代码只认函数指针，具体页面自己填函数。**

C++ 的 `virtual` 只是编译器帮你生成这张表，并在调用时自动选对函数。

### 表盘页 = 在公共 Page 后面再跟私有成员

C++：`class Dialplate : public PageBase` 里面还有 `View`、`Model`、`timer`、`recState`。

C 等价写法：

```c
typedef struct {
    Page          base;        /* 必须放第一项，才能当 Page* 用 */
    DialplateView view;        /* 控件句柄 */
    DialplateModel model;      /* 业务数据接口 */
    lv_timer_t   *timer;
    int           rec_state;   /* READY / RUN / PAUSE / STOP */
    lv_obj_t     *last_focus;
} DialplatePage;
```

`base` 放第一项，是 C 里常见的「继承」：`(Page *)dial` 就是那张公共头。

## 3. 好在哪里：资源按状态机开关

调度器里的状态和 C 枚举一一对应：

```c
enum {
    PAGE_IDLE,
    PAGE_LOAD,             /* 调 on_load / on_did_load */
    PAGE_WILL_APPEAR,      /* 调 on_will_appear */
    PAGE_DID_APPEAR,       /* 调 on_did_appear，然后进入 ACTIVITY */
    PAGE_ACTIVITY,         /* 页面正在前台 */
    PAGE_WILL_DISAPPEAR,   /* 调 on_will_disappear */
    PAGE_DID_DISAPPEAR,
    PAGE_UNLOAD            /* 调 on_unload / on_did_unload */
};
```

表盘把「申请 / 释放」钉死在对应状态上，这是框架真正值钱的地方：

| 时机（C 回调） | 表盘做什么 | 对应你平时写 C 该放哪 |
|----------------|------------|------------------------|
| `on_load` | 初始化 Model、`lv_obj` 创建、绑按键回调 | `xxx_init()`，malloc、建控件 |
| `on_will_appear` | 把三个按钮放进编码器 group，恢复上次焦点 | 打开输入、刷新一帧 |
| `on_did_appear` | `lv_timer_create(1s)` 开始刷速度 | 启动周期任务 |
| `on_will_disappear` | 记住焦点、`lv_group_remove_all`、删 timer | **先停定时器再切页** |
| `on_unload` | Model 反初始化、删控件 | `xxx_deinit()`，free |

如果用纯 C 手写多页面，也建议做成同一张表，而不是在 `switch(g_page)` 里到处 `if`。  
漏停 timer、漏摘 group，就是 HardFault 或花屏的常见原因。

## 4. 好在哪里：一页拆成三块（MVP）

源码三个文件，用 C 看就是三个 `.c`，三个结构体，禁止互相乱调。

```c
/* view：只碰 LVGL，不读 GPS */
typedef struct {
    lv_obj_t *label_speed;
    lv_obj_t *btn_map;
    lv_obj_t *btn_rec;
    lv_obj_t *btn_menu;
} DialplateView;

void DialplateView_Create(DialplateView *v, lv_obj_t *root);
void DialplateView_Delete(DialplateView *v);

/* model：只提供数据/命令，不创建控件 */
typedef struct {
    float speed_kph;
    float distance_km;
} DialplateModel;

void DialplateModel_Init(DialplateModel *m);
void DialplateModel_Deinit(DialplateModel *m);
int  DialplateModel_GpsReady(DialplateModel *m);
void DialplateModel_RecorderCmd(DialplateModel *m, int cmd);

/* presenter：粘合上面两块，处理按键状态机 */
```

规则用 C 说更直白：

- **view.c**：可以 `lv_label_set_text`，禁止 `HAL_GPS_GetInfo()`
- **model.c**：可以问「GPS 好了没、开始录音轨」，禁止拿 `lv_obj_t *`
- **presenter.c**：按键、页面跳转、READY/RUN/PAUSE/STOP 这种 **界面状态**

表盘长按录轨：presenter 里判断长按和当前 UI 状态；真正开文件是 model 发一条「开始录」命令。  
以后换 SD 卡库或换 GPX 格式，改 model 即可，按钮逻辑不用动。

这和驱动分层一样：`xxx_hal.c` / `xxx_core.c` / `xxx_app.c` 不许循环 `#include`。

## 5. 好在哪里：页面栈，而不是一个全局页号

C 项目常写 `static int g_page;`。  
本仓库是 **栈**：开机推进 Startup，结束时用 Replace 换成 Dialplate；从表盘再 Push 进地图，返回就是 Pop。

用 C 描述：

```c
Page *stack[8];
int   top;

void page_push(const char *name)
{
    Page *next = page_create(name);   /* 见下一节工厂 */
    if (top >= 0)
        page_leave(stack[top]);       /* 调 will/did_disappear */
    stack[++top] = next;
    page_enter(next);                 /* 调 load / appear */
}

void page_pop(void)
{
    page_leave(stack[top]);
    page_destroy(stack[top--]);
    page_enter(stack[top]);
}
```

好处：地图页不用知道「返回后是表盘还是别的页」，只调用 Pop。  
多层菜单（表盘 -> 系统信息 -> 某一项）用栈比用一堆 `if (from == ...)` 干净。

源码里的 `Push` / `Pop` / `Replace` 就是这三件事。Startup 用 Replace 而不是 Push，是因为开机动画不必压在栈底占一份缓存。

上面伪代码为了好懂，把「创建页面」写在 Push 里。真实实现是：**Install 时 new 进页面池，Push 只按名字找指针再压栈**。细节见文档 14。

## 6. 工厂：用名字创建页面（C 就是函数表）

C++ 的 `new Page::Dialplate` 对 C 就是「按名字找创建函数」：

```c
typedef Page *(*PageCreateFn)(void);

static const struct {
    const char    *name;
    PageCreateFn   create;
} k_page_table[] = {
    { "Dialplate",   Dialplate_Create },
    { "LiveMap",     LiveMap_Create },
    { "SystemInfos", SystemInfos_Create },
    { "Startup",     Startup_Create },
};

Page *page_create(const char *name)
{
    int i;
    for (i = 0; i < (int)(sizeof(k_page_table)/sizeof(k_page_table[0])); i++) {
        if (strcmp(k_page_table[i].name, name) == 0)
            return k_page_table[i].create();
    }
    return NULL;
}
```

`AppFactory.cpp` 里的 `APP_CLASS_MATCH` 就是上面这个表。  
新加一页：写 Create 函数，往表里加一行——对应文档 04 里的「复制模板 + Install + APP_CLASS_MATCH」。

## 7. 对照：表盘生命周期的 C 伪代码

下面不是工程里的原文件，是把 `Dialplate.cpp` 翻译成你会写的 C：

```c
static void dial_on_load(Page *page)
{
    DialplatePage *d = (DialplatePage *)page;
    DialplateModel_Init(&d->model);
    DialplateView_Create(&d->view, page->root);
    lv_obj_add_event_cb(d->view.btn_map, on_event, LV_EVENT_ALL, d);
    lv_obj_add_event_cb(d->view.btn_rec, on_event, LV_EVENT_ALL, d);
    lv_obj_add_event_cb(d->view.btn_menu, on_event, LV_EVENT_ALL, d);
}

static void dial_on_will_appear(Page *page)
{
    DialplatePage *d = (DialplatePage *)page;
    lv_group_t *group = lv_group_get_default();
    lv_group_add_obj(group, d->view.btn_map);
    lv_group_add_obj(group, d->view.btn_rec);
    lv_group_add_obj(group, d->view.btn_menu);
    lv_group_focus_obj(d->last_focus ? d->last_focus : d->view.btn_rec);
    dial_update(d);                  /* 先刷一次速度，避免空白 */
}

static void dial_on_did_appear(Page *page)
{
    DialplatePage *d = (DialplatePage *)page;
    d->timer = lv_timer_create(on_timer, 1000, d);  /* 1 秒刷新 */
}

static void dial_on_will_disappear(Page *page)
{
    DialplatePage *d = (DialplatePage *)page;
    lv_group_t *group = lv_group_get_default();
    d->last_focus = lv_group_get_focused(group);
    lv_group_remove_all_objs(group);
    lv_timer_del(d->timer);
    d->timer = NULL;
}

static void dial_on_unload(Page *page)
{
    DialplatePage *d = (DialplatePage *)page;
    DialplateModel_Deinit(&d->model);
    DialplateView_Delete(&d->view);
}

static const PageOps k_dial_ops = {
    .on_load = dial_on_load,
    .on_will_appear = dial_on_will_appear,
    .on_did_appear = dial_on_did_appear,
    .on_will_disappear = dial_on_will_disappear,
    .on_unload = dial_on_unload,
};
```

读源码时，看到 `void Dialplate::onViewDidAppear()`，就把它想成 `dial_on_did_appear()`。

## 8. 读源码时的 C++ 对照表

| 你在源码里看到 | 用 C 怎么想 |
|----------------|-------------|
| `class Dialplate : public PageBase` | `struct { Page base; ... }` |
| `virtual void onViewLoad()` | `ops->on_load` 函数指针 |
| `Model.Init()` / `View.Create()` | 调另外两个 .c 的 init |
| `_Manager->Push("Pages/LiveMap")` | `page_push("LiveMap")` |
| `new Page::Dialplate` | `malloc` + 填 ops 表 |
| `delete` / 析构 | `deinit` + `free` |
| `this` | 传入的 `Page *` 或 `DialplatePage *` |
| `namespace Page` | 只是名字隔离，可忽略 |

## 9. 一句话记住

框架好在：**调度器只管状态机和页面栈，每个页面用同一张回调表管理创建/显示/隐藏/销毁；界面、业务、按键再拆成三个 C 模块。**

不是 C++ 语法高级，而是把你平时用 C 也该遵守、却经常顾不上的「init/deinit 成对、切页先停 timer」写成了强制流程。
