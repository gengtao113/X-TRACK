# 05 学习路径

最值得学的不是 AT32 外设驱动，而是：在 512KB RAM 的裸机上，把 GUI 做成可维护的应用框架。多数 MCU + LVGL 项目会把读传感器、算速度、画控件写在同一个文件里；本仓库把这三件事拆开了。

## 四个优先点

### 1. 页面生命周期（PageManager）

把 Android Activity 那套搬到 LVGL：控件何时创建、编码器焦点何时挂上、定时器何时停、离开页如何记住焦点。没有这套状态机，多页面 LVGL 很容易泄漏对象、抢输入、切页闪一下。

读：文档 [14-PageManager-C语言.md](14-PageManager-C语言.md)，再对照 `Utils/PageManager/` -> `Pages/_Template/` -> `Pages/Dialplate/Dialplate.cpp`

### 2. 发布订阅（DataCenter）

页面不读硬件。四种动作：Publish / Pull / Notify / Timer。传感器可以 5Hz 更新，表盘 1Hz 刷新，录轨、校时、地图各自订阅。

读：`DP_LIST.inc` -> `DP_GPS.cpp` -> `DialplateModel.cpp`

### 3. MVP 三文件强制分层

View / Model / Presenter 职责钉死。换屏幕或换 GPS 模块时，表盘交互几乎不用动。

### 4. HAL + 模拟器

接口在 `App/Common/HAL`，MCU 与 Simulator 各写一份实现。GUI 和 DataProc 可以先在 PC 上跑。这比会写 ST7789 驱动更能提高开发速度。

## 推荐阅读顺序

```
1. USER/main.cpp
2. USER/App/App.cpp
3. 文档 14（PageManager）+ Utils/PageManager/
4. Pages/_Template/
5. Pages/Dialplate/Dialplate.cpp
6. Pages/Dialplate/DialplateModel.cpp
7. Utils/DataCenter/
8. Common/DataProc/DP_GPS.cpp
9. Common/DataProc/DP_SportStatus.cpp
10. USER/HAL/HAL.cpp
```

地图瓦片（`MapConv` / `TileConv`）、轨迹压缩（`PointContainer` / `TrackFilter`）、JSON 掉电保存也很精彩，但更偏产品算法。框架四条吃透后再读 `LiveMap` 更划算。

## 二线专题（框架过关后再看）

| 专题 | 路径 | 为什么有价值 |
|------|------|----------------|
| 离线地图 | `Utils/MapConv`、`Utils/TileConv`、`Pages/LiveMap` | 小内存动态加载瓦片 z/x/y |
| 轨迹压缩 | `Utils/PointContainer`、`Utils/TrackFilter` | 拐点提取 + 可视区裁剪 |
| 掉电保存 | `Utils/StorageService`、`DP_Storage` | JSON 键值，关机写盘 |
| HardFault 追踪 | `Libraries/cm_backtrace` | Cortex-M 出错回溯 |
| 合作式任务 | `Libraries/MillisTaskManager` | 无 RTOS 的周期任务 |
