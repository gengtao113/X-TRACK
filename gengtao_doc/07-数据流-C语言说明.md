# 07 数据流：用 C 语言怎么理解

DataCenter 不是数据库，是 **按名字找对方、用回调传结构体** 的总线。  
对只用 C 的人，这就是「带名字的邮箱 + 函数指针回调」，和写 CAN 应用层、写菜单消息、写 `file_operations` 是同一类手法。

本文把 `03-数据流.md` 翻成 C 的说法。源码仍是 C++，看到 `account->Publish()` 就当成 `Account_Publish(account)`。

页面框架的 C 说明见：[06-页面框架-C语言说明.md](06-页面框架-C语言说明.md)。

---

## 1. 没有总线时，C 工程通常长什么样

```c
void dial_update(void)
{
    GPS_Info_t gps;
    HAL_GPS_GetInfo(&gps);          /* 表盘直接读硬件 */
    speed = gps.speed;
    lv_label_set_text(...);
}

void map_update(void)
{
    GPS_Info_t gps;
    HAL_GPS_GetInfo(&gps);          /* 地图再读一遍 */
}

void rec_task(void)
{
    GPS_Info_t gps;
    HAL_GPS_GetInfo(&gps);          /* 录轨又读一遍 */
    gpx_write(&gps);
}
```

问题：

- 换 GPS 模块，三个文件都要改
- 表盘 1Hz 刷新、录轨可能 1Hz、GPS 实际 5Hz，大家抢着读串口
- 页面和 GPX 写文件缠在一起，没法单独测

DataCenter 要做的是：**硬件只允许一个节点读，别人用名字订阅这份数据。**

## 2. Account = 带名字的邮箱

C++ 的 `class Account` 对 C 就是：

```c
typedef struct Account Account;

typedef struct {
    int   event;       /* PUBLISH / PULL / NOTIFY / TIMER */
    Account *tran;     /* 发送方 */
    Account *recv;     /* 接收方 */
    void *data_p;
    uint32_t size;
} AccountEvent;

typedef int (*AccountCallback)(Account *acc, AccountEvent *ev);

struct Account {
    const char *id;            /* "GPS" / "SportStatus" / "DialplateModel" */
    void *user_data;           /* 页面 Model 会把 this 放这里 */
    AccountCallback on_event;  /* 收到消息时调用 */
    Account *pubs[8];          /* 我订阅了谁 */
    int n_pub;
    Account *subs[8];          /* 谁订阅了我 */
    int n_sub;
    uint8_t *cache[2];         /* 乒乓缓存，bufSize==0 则没有 */
    uint32_t cache_size;
    lv_timer_t *timer;
};
```

所有 Account 挂在一个中心上，中心名叫 `"CENTER"`：

```c
typedef struct {
    const char *name;
    Account *list[32];
    int n;
} DataCenter;

static DataCenter g_center = { .name = "CENTER" };

Account *center_find(const char *id)
{
    int i;
    for (i = 0; i < g_center.n; i++)
        if (strcmp(g_center.list[i]->id, id) == 0)
            return g_center.list[i];
    return NULL;
}
```

`new Account("GPS", &center, sizeof(GPS_Info_t))`  
= `malloc` 一个 Account，`id="GPS"`，向中心登记，并申请两块等长缓存（乒乓）。

`Subscribe("GPS")` = 在自己的 `pubs[]` 里记下 GPS 那个指针，同时让 GPS 的 `subs[]` 记下自己。  
之后两边就能互相发消息，不必 `#include "DP_GPS.h"`。

## 3. 四种通信（全是调对方的 on_event）

| 你在源码里看到 | C 怎么理解 | 谁主动 |
|----------------|-------------|--------|
| `Commit` + `Publish` | 把数据写入自己的乒乓缓存，再挨个通知订阅者：`event=PUBLISH` | 发布者推 |
| `Pull("GPS", &gps, sizeof(gps))` | 找到名为 GPS 的账号，调它的回调：`event=PULL`，把结果填进 `&gps` | 订阅者拉 |
| `Notify("Recorder", &cmd, sizeof(cmd))` | 找到 Recorder，调它的回调：`event=NOTIFY`，带命令 | 订阅者下命令 |
| `SetTimerPeriod(500)` | 给这个账号挂 `lv_timer`，到点调回调：`event=TIMER` | 自己周期跑 |

方向记一句：

- **Publish**：我有新数据，推给所有订阅我的人  
- **Pull**：我现在就要一份，去问发布者（发布者可以现读 HAL）  
- **Notify**：不是传数据，是发命令（开始录、改状态栏）  
- **Timer**：闹钟，到点自己干活

`AccountMain` 是中心自带的大号账号，构造时会订阅 **所有** 子节点。开机 `LOAD`、关机 `SAVE` 就是它 `Notify("Storage", ...)`，不必每个页面自己调存盘。

## 4. GPS 节点：定时读 HAL，再 Publish

源码：`DP_GPS.cpp`。C 伪代码：

```c
static int gps_on_event(Account *acc, AccountEvent *ev)
{
    if (ev->event == EVENT_TIMER) {
        GPS_Info_t gps;
        HAL_GPS_GetInfo(&gps);

        if (gps.satellites >= 3) {
            Account_Commit(acc, &gps, sizeof(gps));  /* 写入乒乓缓存 */
            Account_Publish(acc);                    /* 通知所有订阅者 */
        }
        return 0;
    }

    if (ev->event == EVENT_PULL) {
        if (ev->size != sizeof(GPS_Info_t))
            return -2;  /* SIZE_MISMATCH */
        HAL_GPS_GetInfo((GPS_Info_t *)ev->data_p);  /* 现读一份给对方 */
        return 0;
    }

    return -3;  /* 不支持的请求 */
}

void DP_GPS_Init(Account *acc)
{
    Account_Subscribe(acc, "MusicPlayer");  /* 定位状态变化时播提示音 */
    Account_SetCallback(acc, gps_on_event);
    Account_SetTimerPeriod(acc, 1000);      /* MCU 上 1Hz */
}
```

要点：

- **只有 DP_GPS 调 `HAL_GPS_GetInfo`**。表盘、地图、录轨都不碰串口。
- 卫星数 >= 3 才 Publish。缓存里没有「无效乱跳点」。
- 表盘要立刻知道「有没有星」，用 Pull：GPS 回调走 `EVENT_PULL` 分支，现读 HAL。

乒乓缓存：Commit 写一块，Publish 读另一块，避免写的时候别人正在读。`bufSize=0` 的节点（Recorder、Storage）没有这块，只靠 Notify/Pull。

## 5. SportStatus：Pull GPS，算完再 Publish

源码：`DP_SportStatus.cpp`。它订阅 GPS，定时器里：

```c
static int sport_on_event(Account *acc, AccountEvent *ev)
{
    if (ev->event != EVENT_TIMER)
        return 0;

    GPS_Info_t gps;
    if (Account_Pull(acc, "GPS", &gps, sizeof(gps)) != 0)
        return 0;

    /* 用经纬度累加里程、算平均速、卡路里 ... */
    sport.speedKph = ...;

    Account_Commit(acc, &sport, sizeof(sport));
    Account_Publish(acc);   /* 表盘 Model 会收到 PUBLISH */
    return 0;
}
```

链路用 C 画就是：

```
HAL_GPS_GetInfo          只允许 DP_GPS 调用
    |
    |  TIMER 1s: Commit+Publish
    v
Account "GPS" 缓存
    |
    |  SportStatus TIMER 里 Pull("GPS")
    v
Account "SportStatus" 算出速度
    |
    |  Publish
    v
Account "DialplateModel" 的 on_event
    memcpy 到 model.sportStatusInfo
    |
    |  表盘 1s Update()
    v
lv_label 显示时速
```

## 6. 表盘 Model：订阅者长什么样

源码：`DialplateModel.cpp`。C 等价：

```c
typedef struct {
    SportStatus_Info_t sport;   /* 缓存，对应 sportStatusInfo */
    Account *account;
} DialplateModel;

static int model_on_event(Account *acc, AccountEvent *ev)
{
    DialplateModel *m = (DialplateModel *)acc->user_data;

    if (ev->event != EVENT_PUBLISH)
        return -3;

    /* 只收 SportStatus 推过来的包 */
    if (strcmp(ev->tran->id, "SportStatus") != 0)
        return -8;
    if (ev->size != sizeof(SportStatus_Info_t))
        return -2;

    memcpy(&m->sport, ev->data_p, ev->size);
    return 0;
}

void DialplateModel_Init(DialplateModel *m)
{
    m->account = Account_Create("DialplateModel", &g_center, 0, m);
    Account_Subscribe(m->account, "SportStatus");
    Account_Subscribe(m->account, "Recorder");
    Account_Subscribe(m->account, "StatusBar");
    Account_Subscribe(m->account, "GPS");
    Account_Subscribe(m->account, "MusicPlayer");
    Account_SetCallback(m->account, model_on_event);
}

int DialplateModel_GpsReady(DialplateModel *m)
{
    GPS_Info_t gps;
    if (Account_Pull(m->account, "GPS", &gps, sizeof(gps)) != 0)
        return 0;
    return gps.satellites > 0;
}

void DialplateModel_RecorderCmd(DialplateModel *m, int cmd)
{
    Recorder_Info_t rec;
    memset(&rec, 0, sizeof(rec));
    rec.cmd = cmd;
    rec.time = 1000;
    Account_Notify(m->account, "Recorder", &rec, sizeof(rec));
}
```

和 View 的分工：Model **不拿 `lv_obj_t *`**，只 Subscribe / Pull / Notify。

`static int onEvent(...)` 必须是 C 式回调（没有隐藏的 this）。真正的 Model 指针放在 `UserData`，回调第一句转回来。这和 `lv_obj_add_event_cb(..., user_data)` 完全一样。

## 7. 节点注册：X-Macro 就是一张表

`DP_LIST.inc`：

```c
DP_DEF(GPS, sizeof(GPS_Info_t));
DP_DEF(SportStatus, sizeof(SportStatus_Info_t));
DP_DEF(Recorder, 0);
/* ... 一共 13 个 */
```

`DataProc.cpp` **两次** include 同一份文件，只是把 `DP_DEF` 定义成不同含义：

第一次：创建账号

```c
#define DP_DEF(NAME, BUF) \
    Account *act##NAME = Account_Create(#NAME, &g_center, BUF, NULL);
#include "DP_LIST.inc"
```

展开后就是：

```c
Account *actGPS = Account_Create("GPS", &g_center, sizeof(GPS_Info_t), NULL);
Account *actSportStatus = Account_Create("SportStatus", ...);
```

第二次：调用各节点自己的 Init

```c
#define DP_DEF(NAME, BUF)  DP_##NAME##_Init(act##NAME);
#include "DP_LIST.inc"
```

C 工程里等价于一张表：

```c
static const struct {
    const char *name;
    uint32_t buf_size;
    void (*init)(Account *);
} k_nodes[] = {
    { "GPS",         sizeof(GPS_Info_t),         DP_GPS_Init },
    { "SportStatus", sizeof(SportStatus_Info_t), DP_SportStatus_Init },
    { "Recorder",    0,                          DP_Recorder_Init },
};
```

加一个业务节点：新写 `DP_xxx.c` 的 Init + on_event，在列表里加一行。不要在 View 里调 HAL。

## 8. 表盘开始录轨（三种动作各用一次）

```c
void on_record_long_press(DialplatePage *d)
{
    /* 1) Pull：现在有没有星 */
    if (!DialplateModel_GpsReady(&d->model)) {
        DialplateModel_PlayMusic(&d->model, "Error");  /* Notify MusicPlayer */
        return;
    }

    /* 2) Notify：命令 Recorder 开始写 GPX */
    DialplateModel_RecorderCmd(&d->model, REC_START);

    /* 3) Notify：命令 StatusBar 显示 REC */
    /* RecorderCommand 里已经顺带 Notify 了 StatusBar */
}
```

速度数字不走这条命令路径，而是 SportStatus 一直 Publish，Model 回调 memcpy，Presenter 每秒 `Update()` 写 Label。

## 9. 读源码时的 C++ 对照表

| 你在源码里看到 | 用 C 怎么想 |
|----------------|-------------|
| `class Account` | 上面的 `struct Account` |
| `new Account("GPS", &center, n)` | `Account_Create("GPS", center, n, NULL)` |
| `account->Subscribe("GPS")` | 两边链表互记对方 |
| `account->Commit(&x, sizeof(x))` | 写入自己的乒乓缓存 |
| `account->Publish()` | for 每个订阅者，调 `on_event(PUBLISH)` |
| `account->Pull("GPS", &gps, n)` | 找到 GPS，调它的 `on_event(PULL)` |
| `account->Notify("Recorder", &cmd, n)` | 找到 Recorder，调它的 `on_event(NOTIFY)` |
| `SetEventCallback(onEvent)` | `acc->on_event = onEvent` |
| `account->UserData` / `this` | 回调里还原拥有者指针 |
| `std::vector<Account*>` | 指针数组 `pubs[]` / `subs[]` |
| `DP_LIST.inc` 两次 include | 一张节点表，创建 + Init 分两遍 |

## 10. 一句话记住

总线好在：**硬件只进一个 Account；页面用名字 Subscribe/Pull/Notify，互不 include。**

这四句话展开、并对照 `Account.cpp` / `DP_GPS.cpp` / `DialplateModel.cpp` 的 C 写法，见：[09-总线四句话-对照源码.md](09-总线四句话-对照源码.md)。  
Publish 是推缓存，Pull 是当场要一份，Notify 是下命令，Timer 是节点自己的周期任务。

对照阅读：

- 账号结构：`USER/App/Utils/DataCenter/Account.h`
- 节点列表：`USER/App/Common/DataProc/DP_LIST.inc`
- 发布者样板：`Common/DataProc/DP_GPS.cpp`
- 计算后再发布：`Common/DataProc/DP_SportStatus.cpp`
- 订阅者样板：`Pages/Dialplate/DialplateModel.cpp`
