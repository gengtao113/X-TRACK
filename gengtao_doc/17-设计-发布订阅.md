# 17 发布订阅：设计思想与实现

对应学习路径第 2 条。四种动作的逐行对照见 [09-总线四句话-对照源码.md](09-总线四句话-对照源码.md)。  
本文回答：**为什么页面不准读 GPS 寄存器，以及一次数据是怎么到 Label 上的。**

源码：`Utils/DataCenter/`，节点表 `Common/DataProc/DP_LIST.inc`，样板 `DP_GPS.cpp`、`DialplateModel.cpp`。

---

## 1. 设计要解决什么

没有总线时，每个页面都 `HAL_GPS_GetInfo()`：

- GPS 解析 5Hz，表盘只要 1Hz，地图、录轨、校时、状态栏再各读一遍
- 换 GPS 模块要改所有页面
- 页面互相 `#include`，最后拧成一团

设计目标：

1. **硬件只进一个节点**（GPS 只在 `DP_GPS.cpp` 读 HAL）
2. **用名字找人**，页面不 include 节点头文件
3. **生产者和消费者频率可以不同**
4. **命令和数据分开**：要一份最新数用 Pull；广播缓存用 Publish；下命令用 Notify

这不是网络中间件，是同一进程里的「按字符串找 Account，调回调」。裸机上没有进程隔离，靠约定不直接调 HAL。

---

## 2. 核心思想（账号 + 四句话）

每个参与者是一个 `Account`：有名字、可订阅别人、可挂 `onEvent`。

全局一个 `DataCenter`（`DataProc::Center()`）。

四种事件：

| 动作 | 事件码 | 方向 | 典型用途 |
|------|--------|------|----------|
| Publish | EVENT_PUB_PUBLISH | 发布者 → 所有订阅者 | GPS/运动数据更新缓存 |
| Pull | EVENT_SUB_PULL | 订阅者 → 发布者（同步） | 表盘问「现在有没有星」 |
| Notify | EVENT_NOTIFY | 订阅者 → 发布者（命令） | 开始录轨、改状态栏、播提示音 |
| Timer | EVENT_TIMER | 节点自己的周期 | GPS 定时读 HAL |

Subscribe 只是**双向记指针**：我记下你，你记下我。没有 Subscribe 就不能 Pull/Notify 那个名字。

缓冲长度 `bufSize`：

- `sizeof(GPS_Info_t)`：这个节点会 Publish，需要乒乓缓存
- `0`：只收命令或只 Pull，不广播。表盘 Model、Recorder、StatusBar 都是 0

## 3. 实现落地

### 3.1 节点怎么注册

`DataProc.cpp` 对 `DP_LIST.inc` 扫两遍：

```c
/* 第一遍：new Account("GPS", center, sizeof(GPS_Info_t)) */
/* 第二遍：调用各文件里的 DATA_PROC_INIT_DEF(GPS) */
```

`DP_LIST.inc` 就是节点清单，加业务先加一行。例如：

```
DP_DEF(GPS, sizeof(HAL::GPS_Info_t));   /* 会 Publish */
DP_DEF(Recorder, 0);                    /* 只收 Notify */
DP_DEF(StatusBar, 0);
```

`DATA_PROC_INIT_DEF(GPS)` 里：Subscribe 依赖、`SetEventCallback`、`SetTimerPeriod`。

### 3.2 Account 里实际存什么（C 视角）

```c
struct Account {
    const char *id;
    Account **subscribers;   /* 谁订了我 → Publish 时遍历 */
    Account **publishers;    /* 我订了谁 → Pull/Notify 按名字找 */
    int (*on_event)(Account *self, EventParam *p);
    uint8_t *cache[2];       /* 乒乓，bufSize==0 则无 */
    void *user;              /* 页面 Model 的 this */
};
```

`EventParam`：`event` + 发送方 `tran` + 数据指针 `data_p` + `size`。  
回调必须检查 `event` 和 `size`，不对就返回错误码。

### 3.3 页面侧怎么接入

表盘不 new `"GPS"` 那个节点，只 new 自己的账号：

```c
account = new Account("DialplateModel", Center(), 0, this);
account->Subscribe("SportStatus");  /* 收 Publish */
account->Subscribe("GPS");          /* 为 Pull 铺路 */
account->Subscribe("Recorder");     /* 为 Notify 铺路 */
account->SetEventCallback(onEvent);
```

`onEvent` 必须是 `static`（C 函数指针），用 `account->UserData` 取回 Model。  
表盘回调**只处理 SportStatus 的 Publish**，拷到 `sportStatusInfo`。GPS 不走这条回调，要的时候再 Pull。

## 4. 跟三条真实数据路径

### 路径 A：GPS 定时推缓存（Publish）

```
HAL MillisTask / LVGL 周期
  → GPS Account 的 EVENT_TIMER
  → DP_GPS::onTimer
       HAL::GPS_GetInfo(&gps)
       卫星数变化 → Notify("MusicPlayer") 播连接音
       卫星 >= 3 → Commit(&gps) + Publish()
  → 遍历 subscribers，EVENT_PUB_PUBLISH
```

SportStatus 节点同样 Publish 运动结构体；表盘 Model 收到后 memcpy。  
Presenter 的 1s timer 只读这份缓存，**不读 HAL**。

### 路径 B：录轨前问有没有星（Pull）

```
长按录轨 → Presenter onRecord
  → Model.GetGPSReady()
       account->Pull("GPS", &gps, sizeof(gps))
  → GPS 节点 onEvent(EVENT_SUB_PULL)
       当场 HAL::GPS_GetInfo 填进 param->data_p
  → 返回 satellites > 0
```

Pull 是同步函数，当前这份以发布者为准。和 Publish 缓存可以不是同一时刻，GPS 节点 Pull 时直接读 HAL。

### 路径 C：开始录轨（Notify）

```
onRecord READY+长按
  → Model.RecorderCommand(REC_START)
       Notify("Recorder", {cmd:START, time:1000})
       Notify("StatusBar", {SET_LABEL_REC, "REC"})
  → Recorder / StatusBar 各自 onEvent(EVENT_NOTIFY)
```

`REC_READY_STOP` 只 Notify 状态栏，不通知 Recorder——预备停，文件还开着。这是命令语义，不是数据广播。

## 5. 设计上的几条硬规则

| 做 | 不要做 |
|----|--------|
| 新传感器：加 DP_xxx + DP_LIST 一行 | 在 View 或 Presenter 里调 HAL |
| 页面 Model Subscribe 名字字符串 | `#include "DP_GPS.h"` |
| 结构体用 DATA_PROC_INIT_STRUCT 清零 | 未 Subscribe 就 Pull/Notify |
| bufSize 与 Publish 结构体一致 | 页面 Account 乱填很大缓冲却从不 Publish |
| 回调检查 event 和 size | 假定 data_p 一定是某种类型 |

StatusBar 比较特殊：既是顶层 UI，又是名为 `"StatusBar"` 的节点，所以各页可以 Notify 它改样式/REC 文字，它自己再 Pull GPS/电量。它**不是** PageManager 页面。
